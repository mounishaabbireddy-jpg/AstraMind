# AstraMind: Hackathon SOP

**1. Purpose**
Define how the AstraMind team builds, tests, and demos the project within the hackathon timeframe: [one-line description of what AstraMind does, e.g., "an AI assistant that ___ for ___"].

**2. Scope**
Covers ideation lock, task division, development, testing, submission, and the final pitch. Anything outside the core MVP is out of scope unless time remains.

**3. Roles and responsibilities**
- **Team lead:** owns timeline, decisions, and submission
- **AI/ML developer:** models, prompts, APIs, data
- **Frontend developer:** UI/UX and demo flow
- **Backend developer:** server, database, integrations
- **Presenter/documentation:** pitch deck, README, demo video

**4. Pre-hackathon checklist**
- Finalize the problem statement and target user
- Set up a GitHub repo, shared docs, and a communication channel
- Prepare API keys, cloud credits, and the dev environment
- Agree on the tech stack, so nobody is learning something new during the event

**5. Execution timeline (example for 24 to 36 hours)**

| Phase | Time | Output |
|---|---|---|
| Ideation lock | 0 to 2 hrs | Problem, solution, MVP feature list |
| Architecture and setup | 2 to 4 hrs | Repo, stack, task assignments |
| Core build | 4 to 18 hrs | Working MVP of main features |
| Integration | 18 to 24 hrs | Frontend and backend connected |
| Testing and bug fixing | 24 to 28 hrs | Stable demo build |
| Pitch prep | 28 to 32 hrs | Deck, demo video, README |
| Submission buffer | Last 2 hrs | Final submission, no new features |

**6. Development rules**
- Build the MVP first. Only one or two "wow" features.
- Commit often to feature branches and merge to main only when working.
- Freeze features 4 to 6 hours before the deadline.
- Keep a fallback demo (a recorded video or mock data) in case live APIs fail.

**7. Testing procedure**
- Test the full demo path end to end at least 3 times
- Check on the demo device and network, including a no-internet fallback
- Verify there are no exposed API keys in the repo

**8. Submission checklist**
- GitHub repo with a clear README (problem, solution, tech stack, setup, screenshots)
- Demo video (2 to 3 min)
- Pitch deck (5 to 7 slides)
- Live demo link, if applicable
- Team details and any required forms

**9. Pitch structure (3 to 5 min)**
1. Problem (30s)
2. Solution: AstraMind (30s)
3. Live demo (90s)
4. Tech and architecture (30s)
5. Impact, scalability, and next steps (30s)
6. Q&A prep: who is answering what

**10. Risk management**

| Risk | Mitigation |
|---|---|
| API or internet failure | Recorded demo and cached responses |
| Scope creep | Strict MVP list owned by the lead |
| Merge conflicts | Branch per person and regular syncs |
| Burnout | Planned breaks and rotating rest slots |
